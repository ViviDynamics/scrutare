# Nare 2026.11.100: pin, streamed cost and three rail option rules

## Goal and design

Move the pinned runtime from nare 2026.11.94 to 2026.11.100, record the cost
that release reports for streamed turns, and close three configuration items
left from the review of the previous change. The rules of
[the previous plan](2026-11-11-nare-native-capabilities.md) stay: the
subprocess boundary, capabilities read from `nare contract`, and nothing that
changes what a default-configuration review sends or how its verdict is derived
(the #51 promotion gate is still open).

Capacity queueing, which the same release range adds, is not part of this
plan. It is opt-in, has its own design questions, and is planned separately,
on top of this work.

No live model call, credential, holdout content or deployment is part of this
work. Every proof runs offline against the installed 2026.11.100 console.

### What the release range changes

nare `2026.11.94..2026.11.100` (commits 629398f, 9a2f439, 1086d5d, and three
that only record benchmarks and evidence):

- Capacity queueing (nare #291): `--capacity-queue`, `--capacity-wait-seconds`,
  `--capacity-refusals`. A provider capacity refusal is waited out and the same
  request is sent again. Off by default. Each queued refusal emits a `progress`
  event with `detail.capacity`; the result and session file gain
  `capacity_refusals` and the result `capacity_wait_seconds`.
- Adaptive capacity (nare #292): `--capacity-adaptive` and four related flags.
  A limit on requests in flight per provider route. Off by default and needs
  the queue. Events carry `detail.capacity_limit`; the result gains
  `capacity_limit` and `capacity_slot_wait_seconds`.
- Streamed cost (nare #304): a streamed openai-rail turn now takes its cost
  from `usage.cost` on the final usage chunk, only from a response that carries
  `x-litellm-*` headers. Before, a streamed turn never had a reported cost.

No existing default changed. Both capacity switches default to off, and their
only other source is `NARE_CAPACITY_*`, which never reaches a session because
Scrutare drops every `NARE_*` variable from the child environment. A switch
has no "off" spelling to pass, so there is nothing to pin in argv, and this
change sends no capacity option at all. What every session does see is the
result line and the session file: they now always carry the four capacity
fields, at zero or null while the queue is off. The decoder ignores fields it
does not read, so they change nothing. The one inherited change is the
streamed cost, which is Task 3.

## Task 1: Pin 2026.11.100

test expectations, tests/test_nare_runtime_pin.py.
Interface: every installation uses release 2026.11.100 at commit
1086d5d155a139ce1deab2668bcbecf806b6df04 in a separate Python 3.14 environment.

- [ ] Move the pin test to the new release and commit, with 2026.11.94 as the
  previous pin that must not remain.
- [ ] Update every pin location and the installed version expectations.
- [ ] Hold the default with tests: a rail sends the same argv whether or not
  the runtime lists the capacity flags; an installed default session is sent no
  capacity option and nare reports the queue unused; and the decoder accepts
  the capacity fields and records of this release without counting anything
  for them.

## Task 2: Three configuration items from the review of #122

Files: config.py, tests/test_rail_options_config.py, docs/config.md.

- [ ] `request_retry_seconds` and an override that turns retries off. The wait
  bound belongs to the resends, so an override whose `request_retries` is 0 or
  `null` no longer inherits the default rail's bound. Before, such an override
  failed at load naming a field it never set. Setting the bound on a rail
  without resends is still refused.
- [ ] An override that inherits `cache_breakpoints` onto a provider that
  refuses it now says the value was inherited and how to clear it, as
  `structured_output` does.
- [ ] `request_retries` is capped at 10. nare accepts any nonnegative integer,
  so the cap allows nothing nare refuses. Ten resends of one request already
  wait out the whole default bound.

## Task 3: Streamed cost

Files: engine/session_output.py (only if the decoder refuses the new output),
tests/helpers/nare_offline_worker.py, tests/fixtures, cost tests,
docs/session-fanout.md.

- [ ] Run a streamed openai session through the installed console with a
  boundary that answers as a LiteLLM proxy does (an `x-litellm-*` header and
  `usage.cost` on the final usage chunk). Check the session and the review
  record the summed amount as `provider_reported`.
- [ ] The same stream from a gateway without the header reports nothing and
  stays unknown. A stream that reports some turns and not others, or that nare
  filled from prices (`estimated: true`), stays unknown.
- [ ] Keep a fixture shaped like the installed console's streamed output and
  decode it in a test that needs no installed runtime.
- [ ] Update the guides that say a streamed session never reports a cost.

The rules do not change: an amount is `provider_reported` only when nare says
none of it was calculated, and a session with incomplete accounting is unknown.

Outcome: the decoder and the reconciliation accepted the installed console's
streamed output as it was, so no engine code changed for this task. A streamed
turn's `cost` event has the shape a buffered one has (`cost`, `estimated`),
and the result and session file sum them the same way. What changed is the
record a streamed session behind LiteLLM ends with, the tests that pin it, and
the guides.

## Review focus

A configuration must produce the argv, records and token accounting it
produced before the bump; only a streamed session's cost may differ, from
unknown to a reported amount. No session is sent a capacity option. Unknown
cost must never be recorded as zero, and a calculated figure must stay unknown.
