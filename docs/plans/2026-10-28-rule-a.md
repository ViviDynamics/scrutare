# Rule A implementation plan

Issue #102. Refs #51 and maintainer ruling issuecomment-6479128978.

## Scope and design

Implement one opt-in whole-cell replay in the evaluator, and one configurable
whole-review retry for the App. Both default off. Keep the off path's artifacts
unchanged. No deployment, live configuration, infrastructure or promotion changes.
Only the separately frozen g5 schedule may call the specified LAN Spark model.

Capture inputs before executing a pipeline. Retain each attempt separately and
select the first successful attempt. Run all evaluator originals before recovery.
Replay the complete pipeline with identical configuration, captured input bytes,
grants, caps, correction policy and timeout. Terminal session failures permit one
retry; completed empty/invalid answers and hard provenance/input/accounting/routing
failures do not. Every attempt remains charged, with separate cumulative usage.

The App's opt-in invokes the same CLI with an explicit bounded retry flag. The CLI
owns capture, whole-pipeline retry and posting, so no failed attempt is posted.
The worker checks an immutable expected head; a moved head supersedes the job.
Posting journals remain authoritative: confirmed or uncertain posting prevents
retry. Retain retry metadata with the accepted run and preserve failed artifacts.

## Review focus

Missing cost events never become complete accounting. Failed findings never fill
an accepted cell. Snapshot mutation blocks further model calls. A posting timeout
never causes duplicate review. Successful runs cannot be rerun for better evidence.
